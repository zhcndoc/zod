Zod 4.5 实现了一种“方法记忆化”模式，使其能够延迟为绑定方法分配内存，直到这些方法被使用（如果确实会被使用）。本文将讨论这一模式。

在 Zod 4.4 中，一个裸的 `z.string()` 会保留 7.5kb 的堆内存。在 Zod 4.5 中，它只保留 784 字节的堆内存。

## 问题

默认情况下，Zod 模式上的所有方法都是*自动绑定*的，这意味着它们不依赖隐式的 `this` 语义来正常工作。这使得以下模式成为可能；如果依赖未绑定的原型方法，否则可能会发生故障或出现意外行为。

```ts
const { parse } = z.string();

parse("some data");
```

这通常有助于防止某些不常见情况下的意外行为。npm 上有一个[软件包](https://www.npmjs.com/package/auto-bind)，专门实现了一些自动绑定工具。但它也有一个缺点，即每个方法现在都是一个占用内存空间的绑定闭包。多个类实例不再能够通过常规的原型链继承来共享一个方法。

## 修复方案

现在，Zod 4.5 通过一种我称为“方法记忆化”的模式，彻底解决了这个问题。

Zod 类在标准 `prototype` 上将其方法定义为*getter*。第一次访问实例的方法时，它会通过标准的原型继承机制回溯到原型。getter 返回一个绑定到访问它的实例的方法实现，并将其作为一个[自有属性](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Object/hasOwnProperty)分配给该实例，从而永久记忆化该方法。因此，对同一方法的后续访问会避免调用 getter 的开销，并直接从自有属性中解析。

这是我之前描述过的自覆盖 getter 的一种更复杂变体。

<Tweet id="1865002498332795032" />

从未使用过的实例方法（而且大多数方法确实不会被使用！）永远不会被实例化，也不会作为自有属性存储在实例上。

## 自有属性与 V8

旧方法的问题因 V8 围绕对象自有属性进行内存分配的一个细节而更加严重。

- 少于 13 个自有属性时，V8 会在一个紧凑的 128 字节后备存储中跟踪它们
- 达到 13 个或更多时，V8 会将存储空间提升至 848 字节
- 达到 21 个或更多时，它会再次提升至 1616 字节

`zod@4.4.3` 中的常规字符串模式携带了 49 个自有属性（40 个方法和 9 个属性），因此每个实例都会获得 1616 字节的后备存储。

```ts
// zod@4.4.3
const s = z.string();
Object.getOwnPropertyNames(s).length; // 49
Object.getOwnPropertyNames(s).filter((k) => typeof s[k] === "function").length; // 40
```

在新系统下，只有六个属性会被急切绑定：`_zod`、`def`、`type`、`format`、`minLength` 和 `maxLength`。其他所有内容都位于具有记忆化功能的原型上。

```ts
// zod@4.5.0
const s = z.string();
Object.getOwnPropertyNames(s).length; // 6
Object.getOwnPropertyNames(Object.getPrototypeOf(s)).length; // 86
```
